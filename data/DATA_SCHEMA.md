# Dataset: Schema, Assumptions & Generation Logic

This is a **hybrid dataset**: real data where real data is actually usable,
calibrated-from-published-statistics where a raw file wasn't obtainable, and
synthetic (from realistic persona archetypes) everywhere else -- so the
joint distribution of demographics, balances, spending and product ownership
resembles a real retail bank rather than independent random noise. All three
tables are keyed on `CustomerID` and are generated by
[`generate_data.py`](generate_data.py) with `RANDOM_SEED = 42` for
reproducibility.

## Data provenance -- what's real, what's calibrated, what's synthetic

We evaluated four public sources (UCI Bank Marketing, IBM TabFormer, Kaggle
Credit Card Customers, Kaggle Churn Modelling). None of them alone covers
demographics *and* balances *and* multi-year transaction history *and*
product ownership, which is what lets one agent answer EDA, segmentation,
explainability, and recommendation queries from a single customer base --
so we still build a hybrid, but now grounded in real data wherever a source
was actually accessible:

| Source | Status | What we used it for |
|---|---|---|
| **UCI Bank Marketing** ([archive.ics.uci.edu/dataset/222](https://archive.ics.uci.edu/dataset/222/bank+marketing)) | ✅ Downloaded live, 45,211 real rows in `data/uci_raw/bank-full.csv` | **Real, row-level**: `Age`, `MaritalStatus`, `EducationLevel`, housing/personal loan uptake, prior-campaign response. See `uci_calibration.py`. |
| **Kaggle Credit Card Customers** ([sakshigoyal7/credit-card-customers](https://www.kaggle.com/datasets/sakshigoyal7/credit-card-customers)) | ⚠️ Calibrated from published stats, no raw file (Kaggle gates bulk download behind an API token we didn't have) | `CardUtilizationPct` sampled from a Beta(2,5) shape, matching the dataset's documented ~27.5% mean, right-skewed utilization distribution. |
| **Kaggle Churn Modelling** ([shrutimechlearn/churn-modelling](https://www.kaggle.com/datasets/shrutimechlearn/churn-modelling)) | ⚠️ Referenced, not incorporated numerically | Considered for CreditScore/product-count shape, but its ~350-850 FICO-style score and Western market context don't transfer to our stated CIBIL/India setting without misrepresenting the source -- documented here rather than silently forced. |
| **IBM TabFormer** ([github.com/IBM/TabFormer](https://github.com/IBM/TabFormer)) | ❌ Blocked -- verified live: the real transaction file is stored via Git LFS and **IBM's own repo has exceeded its LFS storage quota**, so it isn't downloadable by anyone right now, not just us. | Not incorporated. Our own transaction generator already produces TabFormer-style sequences (merchant, category, amount, timestamp, channel) and stands in for it; swap-in-ready if a file becomes available later. |

Why UCI's `balance` field isn't used directly: it's a 2008-2010 Portuguese
current-account balance in EUR, not comparable in currency, era, or economic
context to an Indian retail bank's rupee balances today. Rather than fabricate
a fake conversion, we only borrow the *shape*: each sampled UCI row's balance
percentile **within its job group** is quantile-mapped into our own
archetype-conditioned synthetic INR balance distribution (see
`build_customers()` in generate_data.py), so a customer who ranks high for
their job in the real data also ranks high in ours, without pretending the
raw numbers are interchangeable.

## 1. `customers.csv` (1,500 rows)

| Column | Type | Provenance | Description |
|---|---|---|---|
| CustomerID | string | synthetic | Primary key, `CUSTxxxxx` |
| Age | int | **real (UCI)** | Bootstrapped from a real UCI row, job-matched to the customer's archetype |
| Gender | string | synthetic | Male / Female / Other |
| Occupation | string | synthetic | Salaried, Self-Employed, Business Owner, Professional, Retired, Student, Homemaker |
| AnnualIncome | float (INR) | synthetic | Log-normal per archetype (UCI has no income field) |
| MaritalStatus | string | **real (UCI)** | Married / Single / Divorced |
| EducationLevel | string | **real (UCI)** | Primary / Secondary / Tertiary / Unknown |
| City | string | synthetic | One of 18 Indian cities |
| CityTier | string | synthetic | Tier1 / Tier2 / Tier3 |
| AccountType | string | synthetic | Savings, Current, Salary, Senior Citizen, Student |
| AccountAgeMonths | int | synthetic | 1-240 |
| AvgMonthlyBalance | float (INR) | synthetic, **real-ranked** | Archetype-conditioned lognormal, quantile-mapped to the sampled UCI row's real balance rank within its job group |
| CreditScore | int | synthetic | 300-900 (CIBIL-style) |
| LoanType | string | **real flags (UCI)** + synthetic | Home/Personal Loan driven by real UCI housing/loan flags; Auto/Education Loan is a synthetic residual (UCI doesn't capture these) |
| LoanStatus | string | synthetic | Active / Closed / Defaulted / None |
| EMI | float (INR) | synthetic | Monthly EMI, 0 if no active loan |
| HasCreditCard | 0/1 | synthetic | |
| CardUtilizationPct | float | **calibrated (Kaggle)** | 0-100, Beta(2,5)-shaped, 0 if no card -- see provenance table above |
| PriorCampaignContacts | int | **real (UCI)** | Number of contacts before this dataset's campaign (`previous`) |
| DaysSinceLastCampaignContact | int or blank | **real (UCI)** | Days since last prior-campaign contact; blank = never contacted (`pdays == -1`) |
| PriorCampaignOutcome | string | **real (UCI)** | Success / Failure / Other / Never Contacted (`poutcome`) |

`customers_ground_truth.csv` is the same table plus a hidden
`_persona_archetype` column (the 7 generation personas below). **This file
is for our own development-time validation only** ("does unsupervised
clustering roughly recover these personas?") — the agent must only ever
read `customers.csv`, never the ground-truth file, otherwise segmentation
is not actually being discovered.

### Persona archetypes used to generate the base population

| Archetype | Weight | Sketch |
|---|---|---|
| Priority Affluent | 12% | High income/balance, many products, high credit score |
| Mass Salaried Regular | 30% | Core salaried middle-income segment |
| Young Digital | 15% | Young, low balance but growing, high txn frequency, low ticket size |
| Dormant Inactive | 15% | Very low transaction frequency, minimal product holding |
| Retiree Conservative | 10% | Older, FD/insurance heavy, stable balance, infrequent large transactions |
| Credit Stressed | 10% | High EMI/card utilization, low credit score, volatile balance |
| Business Growth | 8% | Self-employed/business owner, high volume, business revenue inflows |

## 2. `products.csv` (1,500 rows, one per customer)

| Column | Type | Description |
|---|---|---|
| CustomerID | string | FK -> customers.csv |
| SavingsAccount | 0/1 | |
| CreditCard | 0/1 | Mirrors `customers.HasCreditCard` |
| FixedDeposit | 0/1 | |
| Insurance | 0/1 | |
| Investment | 0/1 | Mutual funds / stocks / NPS |
| Loan | 0/1 | Mirrors `customers.LoanStatus != None` |
| NumProductsOwned | int | Row-wise sum of the six flags above |

## 3. `transactions.csv` (~330k-420k rows, 24 months of history)

| Column | Type | Description |
|---|---|---|
| TransactionID | string | Primary key |
| CustomerID | string | FK -> customers.csv |
| Date | date | Between `REFERENCE_DATE - 24mo` and `REFERENCE_DATE` (2026-07-25) |
| Merchant | string | e.g. "BigBasket", "Employer Payroll" |
| Category | string | Groceries, Dining, Fuel, Utilities, Shopping, Entertainment, Travel, Healthcare, Education, Rent, Salary Credit, Transfer, ATM Withdrawal, Investment, Insurance Premium, EMI Payment, Online Services, Interest Credit, Business Revenue |
| Amount | float (INR) | Log-normal, scaled per archetype and category |
| DebitCredit | string | Debit / Credit |
| Location | string | Usually the customer's home city (~8% out-of-city for travel realism) |
| Channel | string | UPI, Debit Card, Credit Card, NetBanking, ATM, Branch |

Transaction volume per customer is Poisson-sampled from an archetype-specific
monthly range (e.g. Dormant: 0-4/month, Priority Affluent: 18-35/month), plus
deterministic recurring transactions layered on top where applicable: monthly
salary credit (salaried/professional), EMI auto-debit (active loan), SIP debit
(investment holders), insurance premium debit, and recurring business revenue
for business owners/self-employed.

## Regenerating the data

The real UCI source file (`data/uci_raw/bank-full.csv`, 45,211 rows, ~4.5MB)
is committed alongside the generator so the real-data provenance above is
directly verifiable -- open it yourself, it's not a claim you have to take on
faith. To re-download it fresh instead:

```bash
mkdir -p data/uci_raw
curl -L -o data/uci_raw/bank_marketing.zip "https://archive.ics.uci.edu/static/public/222/bank+marketing.zip"
unzip -o data/uci_raw/bank_marketing.zip -d data/uci_raw
unzip -o data/uci_raw/bank.zip -d data/uci_raw   # produces bank-full.csv
```

Then regenerate the derived tables:

```bash
cd data
python generate_data.py
```

Deterministic given the fixed seed and the UCI file's fixed row order —
re-running produces byte-identical output, which keeps EDA/segmentation
results reproducible across demo runs.
